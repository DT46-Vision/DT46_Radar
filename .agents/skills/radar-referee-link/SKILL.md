# 雷达无线链路和裁判串口

依据《RoboMaster 2026 机甲大师高校系列赛通信协议 V2.0.0》（2026-06-26）。官方 PDF 更新后只改本技能。更早版本里 `0x0305` 的长度不同，不用 V1.1.0 的字段说明覆盖这里。

信息波和干扰波从空中收。标记、密钥校验和双倍易伤经裁判串口发。雷达不发射信息波或干扰波。

## 雷达无线链路：只收

官方信号发射源广播，雷达用 SDR 解调。下面命令都是发射源到雷达，10 Hz。

| 命令 | 内容 |
|---|---|
| `0x0A01` | 对方英雄、工程、3 号和 4 号步兵、空中、哨兵的坐标，单位厘米 |
| `0x0A02` | 对方血量 |
| `0x0A03` | 对方剩余允许发弹量 |
| `0x0A04` | 对方金币和占领状态 |
| `0x0A05` | 对方增益、哨兵姿态、存活或无敌状态 |
| `0x0A06` | 对方干扰波密钥，6 字节，每位是 ASCII 字母或数字 |

这条链路没有己方坐标。

加密等级在常规链路的 `0x020E` 里，开局为 1，最高为 3。接收顺序可以先解低等级干扰波，等级到 3 后再切信息波。解调实现参考 [PnX 2026 无线](https://github.com/PnX-HKUSTGZ/RoboMaster-2026-Radar-Wireless) 或 [SHARK radio](https://github.com/JNU-SHARK/shark-radar-radio)，不在本仓库重写一套发射端。

## 常规链路：裁判串口

雷达通过裁判系统常规链路收发。串口只由一个进程写。

### 标记是上报坐标

`0x0305`，雷达发往服务器，再送到己方所有选手端小地图。频率上限 5 Hz，数据段 48 字节：双方各 6 台车的 x、y，各 2 字节，单位厘米。顺序是对方英雄、工程、3 号步兵、4 号步兵、空中、哨兵，然后己方同样六台。

协议写明：己方某车的 x、y 都是 0 时，视为这帧没有发送该车坐标。超出边界时显示在对应边缘。

标记进度不是雷达自己填的。服务器以 1 Hz 用 `0x020C` 发回 2 字节。对方该车进度 ≥100 置 1，己方该车进度 ≥50 置 1。位序从对方英雄到己方哨兵，另有空中机器人被激光瞄准和反制的位。组帧时打开协议原文核对位号。

### 密钥和双倍易伤都在 0x0121

`0x0121` 是雷达自主决策指令，8 字节，经串口发给服务器。

- 第 0 字节：双倍易伤计数。开局为 0。要触发时在当前值上加 1，必须单调且每次只加 1。当时 `0x020E` 表明有机会才会生效。对方正在双倍易伤时再请求，会排到这一次结束之后。
- 第 1 字节是指令类型，第 2 到第 7 字节是 6 位密钥。类型 `1`：更新己方密钥，只在开局、以及对方破解成功导致己方干扰难度升级时有效。类型 `2`：提交从 `0x0A06` 解出的对方密钥供服务器验证；每次提交后 10 秒内再次提交无效。

### 服务器每秒告诉雷达能不能做

`0x020E`，1 Hz，1 字节，服务器发往雷达。

- bit 0–1：剩余双倍易伤机会，开局 0，最多 2。
- bit 2：对方是否正在被双倍易伤。
- bit 3–4：己方加密等级，也就是对方干扰波难度，开局 1，最高 3。
- bit 5：当前是否可以修改己方密钥。

停留区域、血量骤降只决定队伍何时把第 0 字节加一。协议不规定这个策略。

SHARK 用机器人交互数据把无敌目标发给己方，那是队伍自定义内容，不是 `0x0121` 的双倍易伤。
